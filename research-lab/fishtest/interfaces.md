## Submission and authentication

| Interface | Verified capability |
|---|---|
| Contributor web UI at `/tests/run` | The official guide instructs a contributor to sign in, complete the form and select **Submit test**. New accounts receive human approval. The primary server validates the session, CSRF token and submitted fields, creates a pending run and redirects to its run page. An independent Fishtest approver must approve it before workers are assigned. |
| Public user API | Anonymous queries expose queued, running and finished jobs and their results. The documented API and registered routes contain no public method for creating a test run. |
| Worker API | An authenticated worker requests an existing task and reports heartbeat, game results or failures. Worker credentials and a GitHub token do not provide an unattended contributor submission interface. |
| CLI, service identity or permitted unattended submission | No supported contributor CLI, machine token for creating runs or published authorization for unattended submissions was identified in the official references. The form's HTTP POST is an implementation detail of the authenticated UI. |

## Form fields and public reads

For a new run, the official UI supports the plain `/tests/run` page. Its handler reads a saved test using `/tests/run?id=<existing-run-id>`, which the UI labels **Reschedule**. Remaining defaults come from server configuration and the signed-in profile. The source supplies no documented query parameters for prefilling arbitrary new-run refs, bench or settings. The lab prints a field sheet for a new job. When reusing an STC run via Reschedule, explicitly select LTC and verify every field and both resolved commits. [Form setup](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/views.py#L2435-L2486) · [Official Reschedule link](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/templates/tests_view.html.j2#L193)

| Anonymous GET on `https://tests.stockfishchess.org` | Response shape at the checked revision |
|---|---|
| `/api/active_runs` | One JSON object keyed by run ID for all unfinished runs, including pending jobs. |
| `/api/finished_runs?page=N` | JSON object keyed by run ID, up to 50 results per 1-based page. Supports `username`, `timestamp`, `success_only`, `yellow_only` and `ltc_only`. Deleted runs are excluded. |
| `/api/get_run/<id>` | One run object with `_id`, flags, `args` and `results`. Heavy task fields are stripped. Unknown IDs return 404. |
| `/api/get_elo/<id>` | For SPRT, one run object with nested `elo.elo`, `elo.ci` (two endpoints of the 95% interval), `elo.LOS` and `elo.LLR`. A non-SPRT run returns `{}`. |
| `/api/calc_elo` | With fixed-game paired outcome counts `LL,LD,DDWL,WD,WW`, returns `elo`, `ci`, and `LOS`. Each paired count refers to one opening played in both colors. SPSA tuning progress is a separate result type. |

Use the verified stage's `args.sprt.state` and lifecycle flags for a promotion decision. Preserve results as observed at their sample size. [Public API implementation](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/api.py#L344-L555) · [SPRT intervals](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/stats/sprt.py#L123-L135)

## Procedure for an authorized contributor

1. **Establish eligibility.** Review the patch, baseline and candidate SHAs, both bench signatures, successful CI and local screening evidence. Check current Fishtest methodology for that kind of change. Ordinary functional changes use STC followed by LTC after an STC pass. Non-regression, speedup, SMP, scaling and tuning experiments have distinct guidance. Discuss exceptions with maintainers where required. [Testing methodology](https://github.com/official-stockfish/fishtest/wiki/Creating-my-first-test#testing-methodology)
2. **Confirm the budget and defaults.** Record the intended stage, thread count, both time controls and option strings, book and depth, adjudication, stop rule, Elo model, bounds, error rates and allowed compute. At the checked revision standard STC uses one thread, `10+0.1`, 16 MiB hash and normalized Elo bounds [0, 2]. Standard LTC uses one thread, `60+0.6`, 64 MiB hash and [0.5, 2.5]. Both use alpha and beta of 0.05. The server sets a ceiling of 800,000 games for a new SPRT run. A typed game limit in a preparation packet does not enforce a lower server limit. If the agreed budget needs a tighter cap, resolve that with project operators before submitting. The guide asks contributors to let standard tests reach their statistical stopping condition. [Form presets](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/templates/tests_run.html.j2) · [Server stopping rule](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/views_run.py#L542-L567)
3. **Reconcile duplicates.** Check the lab ledger and pending submission packets. Inspect `GET /api/active_runs` for all submitters, then search finished runs by relevant history, including failed and inconclusive outcomes. `GET /api/finished_runs?page=1` returns up to 50 runs keyed by ID. Continue pagination through the applicable time window and record its coverage. Compare resolved SHAs, patch mechanism and stage settings. A passing STC and its proposed LTC have distinct time controls. Link an existing equivalent run to the packet. Document the scientific reason for a retest. Record search failures or bounded coverage explicitly and ask the human to reconcile unresolved duplicates. [Public read API](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/api.py#L344-L410)
4. **Submit once.** The contributor confirms permission and budget for this exact stage, verifies the public fork and refs still resolve to the packet SHAs, and checks both network names are available to Fishtest. Enter the packet using the official form. Save the returned `/tests/view/<run-id>` URL in the ledger and verify the server-resolved SHAs and settings. If the POST outcome is ambiguous or its response is lost, reconcile the submitter's new pending and finished runs before deciding on any retry. A pending run is already submitted. [Contributor workflow](https://github.com/official-stockfish/fishtest/wiki/Creating-my-first-test#run-your-test) · [Server form checks](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/views_run.py)
5. **Monitor and retain evidence.** Poll the first-party `GET /api/get_run/<run-id>` with bounded retries and backoff. Preserve the observation time, raw public response, config, SHAs, bench signatures, W/D/L, pentanomial counts and `args.sprt` state, bounds and LLR. If the server reports a stopped, deleted or failed run, capture the reason and review its action log. A finished run with empty SPRT state supplies no accepted sequential result. Record network outages as stale or unknown status. Treat any revision or stage change as a distinct packet. Link the applicable finished official runs and new bench in an upstream PR once the rest of the lab and Stockfish gates pass. [Run schema](https://github.com/official-stockfish/fishtest/blob/a71b7cbaf674ed0aaee956eefda9abb71fc8fbf2/server/fishtest/schemas.py#L713-L794) · [Contribution rules](../../CONTRIBUTING.md)
