# EXP-COMPRESSION-001 — directly runnable Stockfish 19 in 88 MB

**Packaging result.** Two independently built native x86-64 UCI launchers reproduce the reported user experience. Select the Windows executable in a chess GUI as a UCI engine. On Linux, make the downloaded file executable and select it the same way. Each accepts normal Stockfish UCI commands and arguments. The optional custom HTML client communicates with that same local engine through a small Python backend. MB is decimal here. The Windows result is 84.18 MiB. It contains the complete official PE, including its embedded NNUE, in 3,145 checksummed MSZIP Cabinet blocks. The fast encoder uses Deflate level 1 and memory level 4. The 88 MB size includes the decoder and launcher. On first use the launcher restores a private, hash-verified executable automatically. Later launches verify the cache and reuse it. Keeping both Windows files uses about 191.31 MB of logical disk space. Upstream's 81.43 MB Windows distribution ZIP is smaller than the directly launchable file. **Historical recovery.** The owner identifies MSZIP and recalls direct chess-GUI and HTML use with a roughly 135 MB input. No original binary, archive, or HTML implementation was recovered. This reconstruction identifies its own execution path: one native build per operating system, with a native UCI backend for HTML. The historical implementation could have used a different build, transparent storage, a backend, or WebAssembly. The verified release inputs here were about 103 MB, so this work establishes the functioning 88 MB package without establishing the historical 34.8% reduction. [Recovery search and provenance](../../proofs/mszip/recovery.md)

**Correctness.** Independent Cabinet extraction reproduced the official SHA-256 on each platform. A second clean build reproduced both launcher digests. Windows and Linux GitHub runners completed UCI startup, returned a legal forced move, exited cleanly, and searched exactly 2,497,913 nodes in the release bench. All 30 Linux performance trials matched NNUE evaluation, fixed-node search results and bench signature. XBoard played a legal mate with both colors, Fastchess completed a normal color-reversed pair, and Chromium received a best move and a stalemate result from the actual packaged engine. [Native CI run](https://github.com/ShadyF4RR/Stockfish/actions/runs/44819051300) · [Linux observations and PGNs](../../proofs/mszip/RUNTIME.md)

**Runtime decision.** On Linux the median time to UCI readiness across ten trials per mode was 0.595 s native, 2.864 s on first use and 0.755 s with the MSZIP cache primed. Peak process RSS was about 317 MiB in all three modes. The median paired cached/native search NPS ratio was 0.968 with a 0.825–1.189 interval on the shared runner. First use has a measurable startup cost. There was no demonstrated improvement in search throughput, engine RAM usage or playing strength. Hardware cache counters were unavailable. The four compatibility games do not measure Elo. Keep this technique available as a distribution option on the experiment branch. [Runtime measurements](../../proofs/mszip/RUNTIME.md)

A second GitHub run measured Windows release and package processes on the same Windows Server 2025 runner. Median readiness in three warm trials per side was **322 ms native and 423 ms packaged**. One empty-cache package launch took **2,899 ms**. Median canonical bench speed was **972,328 vs 954,130 NPS**. Peak sampled process-tree working sets were **287.0 vs 264.5 MiB**. These short samples at 50 ms resolution, including shared pages, cannot establish a RAM or speed advantage.
