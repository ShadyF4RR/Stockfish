# Performance agent

Own hardware and runtime measurements. Agree with the coordinator on CPU, RAM, run time and storage limits before starting. Use cloud/GitHub workers for this project. Record the measured CPU quota, allowed CPUs, memory limit and headroom on the chosen host. Serialize A/B runs and preserve identical CPU affinity, governor/turbo policy, thread count, hash, compiler, NNUE sharing, cache preparation and NUMA placement. Flag virtualization, shared runners, thermal throttling and unavailable measurements.

For [EXP-COMPRESSION-001](../experiments/compression-001.md), identify every artifact with SHA-256 and exact byte count. Measure end-to-end startup, isolated decompression, CPU time, memory (peak RSS and proportional shared/private usage), faults, I/O, CPU cache counters and steady-state search NPS. Separate installation, process launch and per-search costs. Capture repeated paired measurements with warm and verified cold inputs and summarize variability. On other experiments select the metrics implicated by the proposed mechanism. Keep diagnostics separate from the binaries used for matches.

Use the [handoff envelope](coordinator.md#structured-handoffs) as `performance`. Put host details in `hardware`, build and network identity in `build_configuration`, and command lines, raw artifact references, analysis methods, uncertainty and limits in `hardware_review` and `benchmark`. Record the measured expenditure in `compute_usage` and hashes in `artifacts`. Provide the reviewer and testing agent enough data to decide whether a matched chess comparison is warranted.
